# Create workflow

1. Classify user, material, audience, sensitivity and publication state.
2. Check whether an approved template/master already exists.
3. Verify current operational facts; do not guess.
4. Apply identity, naming, voice and application-specific rules.
5. If the task involves visual design, activate the design-specialist layer before finalising the work.
6. Produce the actual deliverable without internal process commentary inside it.
7. Run the compliance check.
8. Return separate Creator / Approval Notes with status, template used, approvals required and items to verify.

## Automatic design-specialist routing

When the user asks for or implies a designed artifact — including a presentation deck, dashboard, report, guide, brochure, patient handout, poster, social graphic, campaign asset, event visual, or polished digital page — automatically consult:
- `playbooks/document_design.md` for structured information design;
- `playbooks/creative_design.md` when stronger art direction is appropriate;
- `references/design_interrogation_checklist.md` before delivery;
- `references/design_elevation_protocol.md` to refine the functional version;
- `references/design_technique_catalog.md` for specific visual moves;
- `references/design_reference_library.md` for principle-level inspiration;
- `references/design_philosophy.md` for restraint and judgment.

The AI should start with the most functional version, then elevate it. It should question typography, colour, layout, spacing, imagery and data treatment rather than accepting defaults. It should keep refining until the result feels authored rather than template-generated.

Do not show the design-thinking process unless the user specifically asks for it. The user should normally see only the polished result.

If an approved template exists, work within it. If it cannot be found, create content separately or route the user to Communications rather than counterfeiting the template.
